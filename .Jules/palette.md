## 2023-10-27 - [Semantic Elements Remove Need for a11y Suppressions]
**Learning:** This SvelteKit app heavily utilizes `<!-- svelte-ignore a11y_... -->` comments on `<div>` and `<p>` elements that are acting as buttons. By simply swapping these out for semantic `<button type="button">` elements, the accessibility warnings naturally resolve, and native keyboard support (focus, space/enter activation) is instantly restored.
**Action:** When seeing `svelte-ignore a11y_*` around click handlers on non-interactive tags (like `<p>` or `<div>`), immediately check if the element can be converted to a `<button type="button">`. **Learning:** Suppressing a11y warnings (`svelte-ignore a11y_click_events_have_key_events`) on non-interactive elements like `div` when `onClick` is provided is an anti-pattern. While Svelte allows `onclick` on any element, it leads to components not being focusable or announced correctly by screen readers.
**Action:** Instead of suppressing a11y warnings, conditionally render semantic interactive elements (like `<button>`) and manage the inner content cleanly using Svelte 5 snippets (`{@render snippet_name()}`). Add button resets and `focus-visible` styling to maintain the design system while significantly improving keyboard navigation.
