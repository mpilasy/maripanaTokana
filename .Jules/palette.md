## 2023-10-27 - [Semantic Elements Remove Need for a11y Suppressions]
**Learning:** This SvelteKit app heavily utilizes `<!-- svelte-ignore a11y_... -->` comments on `<div>` and `<p>` elements that are acting as buttons. By simply swapping these out for semantic `<button type="button">` elements, the accessibility warnings naturally resolve, and native keyboard support (focus, space/enter activation) is instantly restored.
**Action:** When seeing `svelte-ignore a11y_*` around click handlers on non-interactive tags (like `<p>` or `<div>`), immediately check if the element can be converted to a `<button type="button">`. ## 2024-03-31 - Semantic Expansion Header for WeatherAlertBanner
**Learning:** The `WeatherAlertBanner.svelte` component used a `<div>` for its expanding header section with `svelte-ignore` comments for a11y warnings, meaning it couldn't receive proper keyboard focus. By converting it to a `<button>` with `aria-expanded` and `aria-controls`, we improved keyboard accessibility. A key lesson is that resetting button styles (`border: none; background: none; font: inherit; color: inherit; width: 100%; text-align: left;`) allows us to use semantic `<button>` elements while retaining the desired visual layout of a `<div>`.
**Action:** Continually look for `svelte-ignore a11y` comments on custom UI components, especially expanding headers and accordions. Replace them with semantic `<button>` elements, resetting the native button CSS to match the original design while providing `focus-visible` states.
