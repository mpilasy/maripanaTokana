## 2023-10-27 - [Semantic Elements Remove Need for a11y Suppressions]
**Learning:** This SvelteKit app heavily utilizes `<!-- svelte-ignore a11y_... -->` comments on `<div>` and `<p>` elements that are acting as buttons. By simply swapping these out for semantic `<button type="button">` elements, the accessibility warnings naturally resolve, and native keyboard support (focus, space/enter activation) is instantly restored.
**Action:** When seeing `svelte-ignore a11y_*` around click handlers on non-interactive tags (like `<p>` or `<div>`), immediately check if the element can be converted to a `<button type="button">`. **Learning:** In Svelte components like `LocationOverrideDialog`, do not ignore `a11y_no_static_element_interactions` on `<div>` elements acting as modals or click handlers. ## 2024-05-18 - A11y Warnings Suppressed
**Learning:** Svelte accessibility warnings are being suppressed (`svelte-ignore a11y_click_events_have_key_events`, `svelte-ignore a11y_no_static_element_interactions`) on `div` and `span` elements acting as buttons throughout the app (`CurrentConditions.svelte`, `WeatherAlertBanner.svelte`, etc.). This means keyboard users and screen readers cannot properly interact with these elements.
**Action:** Replace clickable `div`/`span` elements with semantic `<button>` elements, applying CSS resets (`border: none; background: transparent; font: inherit; color: inherit; text-align: left; width: 100%;`) to maintain existing styling while gaining built-in accessibility and adding `focus-visible` states.
