## 2023-10-27 - [Semantic Elements Remove Need for a11y Suppressions]
**Learning:** This SvelteKit app heavily utilizes `<!-- svelte-ignore a11y_... -->` comments on `<div>` and `<p>` elements that are acting as buttons. By simply swapping these out for semantic `<button type="button">` elements, the accessibility warnings naturally resolve, and native keyboard support (focus, space/enter activation) is instantly restored.
**Action:** When seeing `svelte-ignore a11y_*` around click handlers on non-interactive tags (like `<p>` or `<div>`), immediately check if the element can be converted to a `<button type="button">`. ## 2024-05-04 - [Svelte Accessibility Pattern for Interactive Containers]
**Learning:** When converting an interactive `<div>` containing nested elements (like a header with a text title and a share button) to a semantic `<button>` to resolve accessibility warnings, Svelte will complain about hydration mismatch if you nest interactive elements (`<button>` inside `<button>`).
**Action:** Instead of making the entire container a `<button>`, keep the container as a layout wrapper (e.g., `<div class="section-header">`) and use a styled `<button>` inside it strictly for the clickable area, placing other interactive elements as siblings inside the wrapper. Add CSS resets (`border: none; background: transparent; font: inherit;`, etc.) to the new button to maintain existing styling, and attach ARIA attributes (`aria-expanded`, `aria-controls`) to complete the accessibility pattern.

## 2024-05-04 - [Hydration Mismatches with Math.random() in Svelte 5]
**Learning:** Using `Math.random()` to generate IDs for `aria-controls` within component initialization causes SSR hydration mismatches, because the server generates a different random number than the client.
**Action:** In Svelte 5, avoid generating random IDs for elements. Use a module-level counter variable inside a `<script module>` block (e.g. `let contentId = 'content-' + idCounter++`) to ensure deterministic ID generation during both SSR and client-side hydration.

## 2024-05-12 - [Disclosure Widgets Should Use Buttons with ARIA Controls]
**Learning:** In Svelte components like `WeatherAlertBanner`, interactive containers functioning as disclosure widgets (expand/collapse panels) were built using `<div>` elements with `svelte-ignore` comments. While this hides the accessibility warnings, it creates a poor experience for screen reader users and requires custom keyboard handlers.
**Action:** Always replace interactive `<div>` disclosure toggles with semantic `<button type="button">` elements. Add `aria-expanded` bound to the state, and `aria-controls` pointing to the target panel's ID. Ensure IDs are deterministically generated (using a module-level counter, as learned previously) to prevent SSR hydration mismatches, and apply CSS resets to the button to preserve its layout.
