## 2023-10-27 - [Semantic Elements Remove Need for a11y Suppressions]
**Learning:** This SvelteKit app heavily utilizes `<!-- svelte-ignore a11y_... -->` comments on `<div>` and `<p>` elements that are acting as buttons. By simply swapping these out for semantic `<button type="button">` elements, the accessibility warnings naturally resolve, and native keyboard support (focus, space/enter activation) is instantly restored.
**Action:** When seeing `svelte-ignore a11y_*` around click handlers on non-interactive tags (like `<p>` or `<div>`), immediately check if the element can be converted to a `<button type="button">`. ## 2025-04-07 - Mitigating Nested Interactions Validation with Semantic Buttons
**Learning:** When refactoring clickable containers from Svelte components (like headers with nested buttons) from pragmatically-ignored non-interactive elements (`<div onclick="...">`) to accessible `<button>` tags, it is crucial to avoid nesting buttons inside one another. Svelte SSR validation throws a `hydration_mismatch` warning (`<button> cannot be a child of <button>`) because the browser strips invalid nested interactive structures.
**Action:** Always wrap the nested elements (like share buttons and expand buttons) inside a flex layout parent (`<div class="header-row">`) instead of applying the clickable button style to the entire container encompassing both buttons. This keeps elements valid without losing existing interactions.
