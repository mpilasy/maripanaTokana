## 2023-10-27 - [Semantic Elements Remove Need for a11y Suppressions]
**Learning:** This SvelteKit app heavily utilizes `<!-- svelte-ignore a11y_... -->` comments on `<div>` and `<p>` elements that are acting as buttons. By simply swapping these out for semantic `<button type="button">` elements, the accessibility warnings naturally resolve, and native keyboard support (focus, space/enter activation) is instantly restored.
**Action:** When seeing `svelte-ignore a11y_*` around click handlers on non-interactive tags (like `<p>` or `<div>`), immediately check if the element can be converted to a `<button type="button">`. **Learning:** In Svelte components like `LocationOverrideDialog`, do not ignore `a11y_no_static_element_interactions` on `<div>` elements acting as modals or click handlers. ## 2024-04-21 - Accessible Disclosure Widgets
**Learning:** For components that expand/collapse content (like `WeatherAlertBanner.svelte`), using a `<div>` with `svelte-ignore` comments breaks screen reader behavior because the state is not communicated. Converting it to a semantic `<button>` with `aria-expanded` and `aria-controls` properly maps it to the standard Disclosure Widget pattern.
**Action:** When implementing collapsible sections or alert banners, always use `<button aria-expanded={isExpanded} aria-controls="panel-id">` for the toggle and `<div id="panel-id">` for the content, applying CSS resets to retain original layout.
